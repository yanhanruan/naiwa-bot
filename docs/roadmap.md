## 已定调整（2026-11-16 review）

适用于所有模块：

- **每个模块结束时部署并做真实 QQ 冒烟检查。** 线上机器人切到新代码，跑一份简短检查清单，避免线上与仓库越差越远。
- **尽早录制真实 SnowLuma 流量**（原始 OneBot 事件存成文件并脱敏），作为 Module 1 / 3 / 5 的测试数据。顺带核实：`time` 格式、`message_id` 在 SnowLuma 重启后是否稳定、@ 与引用段的实际格式。
- 使用 Git：每个模块在独立分支上完成，review 后再合并。

按模块：

- **Module 2**：定位为基础设施：SQLite、迁移执行器、三个现有存储的移植、备份。Module 5 / 6 / 9 需要的表通过各自的迁移添加。同时去掉内存中的整份记录副本，否则多进程写入的问题仍在。需要决定用 `node:sqlite`（零依赖，需 Node ≥ 22.13，尚未标记稳定）还是 `better-sqlite3`（稳定，但是编译型依赖）。
- **Module 2 之后：代号改为全局。** 现在模型看到的代号（`u1`、`u2`）按会话编号、只存在内存中。有了持久化存储后，改成**每个人一个全局、持久的代号**，同一个人在任何群和私聊里代号都相同，便于奶蛙认人。
- **Module 3**：加入发送节流（非官方 QQ 客户端发得太快有封号风险）；加入以 `message.key` 关联的基础结构化日志（原属 Module 10，提前）。
- **Module 4**：加入成本上限（例如按会话限速、每日 token 上限）。
- **Module 7 之前的临时闸门**：奶蛙进任何群之前，先加一个简单规则：只在私聊、被 @、或有人引用奶蛙的消息时回复。Module 7 完成后替换。
- **Module 9**：精简。目前没有任何发布或私信动作的执行器，审批没有对象。先做持久化开关和 CLI 与运行中服务的通信；有需要审批的动作时再做审批。

## Module 6 设计要求：跨会话认人（已定：保守）

目标：奶蛙像真人一样认人，在不同群里都知道“这是同一个人”，但懂分寸。

记忆分三层：

| 层次 | 例子 | 可见范围 |
| --- | --- | --- |
| 对这个人的印象 | 昵称、兴趣、关系好坏、说话风格 | **跟着人走**：这个人在任何群或私聊发言时都可召回 |
| 会话里发生的具体事 | “他在群 A 说今天考试挂了” | **只在原会话**：群 A 的事只在群 A 召回 |
| 私聊内容 | 私聊里说的任何事 | **只在该私聊**：永远不进任何群 |

要求：

1. 新增一种“跟着人走”的可见范围（例如 `person:<用户key>`），专门存放对这个人的印象。它与 `conversation:<会话key>`（只在该会话可见）和 `private:<某人>`（某人的私事）语义不同，不复用已有前缀。
2. 默认采用**保守**策略：具体事件不跨会话。以后如需开放，按群单独设置（例如“他本人在场时可想起他在其他群的事”），默认关闭。
3. 从私聊提炼出的印象不能带有私聊细节，不能让群友推断出私聊内容。是否允许私聊信息提炼成印象，在设计时单独说明。
4. 取消 `self` 请求者“能看全部记录”的特权；角色自身记忆只按 `access === 'self'` 读取（Module 1 已在处理器层先做了过滤）。
5. 验收补充：同一个人在群 A 和群 B 发言，奶蛙在两边都能认出他（印象一致）；群 A 发生的具体事在群 B 不会被召回；私聊内容在任何群都不会出现。
