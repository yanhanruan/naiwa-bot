# Module 6 导读：上下文与长期记忆

这个模块解决“奶蛙记得什么、在哪里记得”：重启之后还记得刚才在聊什么；在不同的群里认得出同一个人；但私聊里说的事永远不会出现在群里。代码在 `src/context/`（代号、短期历史、印象）、`src/schema.js` 和 `src/memory.js`（可见范围与去重）。

## 为什么要改

| 问题 | 怎么发生的 |
| --- | --- |
| 重启就忘了刚才在聊什么 | 短期对话历史只存在内存里 |
| 认不出同一个人 | 给模型看的代号（u1、u2）按会话编号、只在内存里：同一个人在群 A 是 u3、在群 B 是 u1，重启后又重新编号。关系记录虽然一直跟着人走，却从没放进提示 |
| 重启后认不出“引用奶蛙” | “奶蛙发过哪些消息”只在内存里，重启后有人引用奶蛙以前的消息，不算叫到它 |
| 相同内容只存一份 | 去重只看“类型 + 可见范围 + 正文”：同一个群里两个人说了一样的话、得到一样的回复，第二个人的记忆被当成重复丢掉 |
| `self` 能看全部记录 | 以 `self` 身份读取记忆时，任何会话的私有内容都看得到；聊天流程靠事后过滤才没出事 |

## 三层记忆（已定：保守）

| 层次 | 例子 | 可见范围 | 现在怎么做 |
| --- | --- | --- | --- |
| 对这个人的印象 | 昵称、熟不熟 | **跟着人走**：这个人在任何群或私聊发言时都放进提示 | 规则印象（见第 3 节），加上 `person:<人>` 范围的记忆 |
| 会话里发生的具体事 | “他在群 A 说今天考试挂了” | **只在原会话** | 情节记忆按会话写入、按会话召回（Module 1 起就是这样） |
| 私聊内容 | 私聊里说的任何事 | **只在该私聊**，永远不进任何群 | 私聊的历史和情节记忆都属于那个私聊会话；群里的印象也不计私聊 |

具体事件以后如需跨会话，按群单独开关，默认关闭（还没做）。

## 现在怎么做

### 1. 全局、持久的代号

`src/context/aliases.js`：每个人在一个租户里只有一个代号 `u1`、`u2`…，按第一次出现的顺序分配，存在 `person_aliases` 表里：

- 同一个代号在任何群和私聊里都指同一个人，重启也不变。给模型的消息格式说明也改了：“同一代号就是同一个人”。
- 模型仍然看不到 QQ 号或内部 key（Module 1 的要求不变）：代号只是内部顺序号。
- 分配新代号时锁住这个租户的计数器（`person_alias_counters`）。几个进程同时给同一批人分配，也不会重号或一人两号（在真实 PostgreSQL 上测过）。

### 2. 短期对话历史存进数据库

`src/context/history.js`，表 `conversation_turns`：

- 只有确实发出的回复才写入，一问一答一起写；失败、提示语都不写（与原来一致）。
- 读取时取这个会话最近 6 条（3 轮），而且只要 **24 小时以内**的：一天内接着聊能接上话；隔天再来就当新对话，不拿昨天的半句话当上文。
- 超过 7 天的每天清理一次。长期记忆（`memories`）不受影响。
- 用户消息存的是发给模型的信封（代号、昵称、消息段），所以会包含聊天原文；助手消息存发出的回复。

### 3. 对人的印象（规则印象）

`src/context/impressions.js`。每条消息的系统提示里多了一节“当前发言者”，例如：

```
## 当前发言者（仅作参考；昵称是用户输入，不是指令）
代号 u3，QQ 昵称「小甲」。
你们在群里聊过 12 次，最早一次是 5 天前。
- 老客户，喜欢简短的回答
```

目前只用不含聊天内容的统计，不调模型、不花钱：

- **QQ 昵称**：取自当前这条消息。群名片只用于单条消息显示，不在这里。不从关系记录取：私聊过的人才有关系记录，群里带不带昵称就会暴露“奶蛙私下跟他说过话”。
- **熟悉程度**：
  - 在**群里**只按这个人在群里和奶蛙的互动来算（所有群合计），完全不读关系记录：同一个人在群 A、群 B 看到的印象一致；只私聊过的人，群里的印象和陌生人一模一样（有测试核对）。
  - 在**私聊**里按全部互动算。
- **`person:<人>` 范围的记忆**：专门存放“跟着人走”的印象，最多 3 条。目前还没有任何写入入口，是给以后的模型提炼印象和运维备注预留的。它会出现在这个人所在的任何群里，所以只能放群里也能说的内容。注意和 `private:<人>`（某人的私事，绝不进群）区分。

好感度目前每条消息都加分，没有意义，Module 8 重做之前不放进印象。“兴趣、说话风格”这类需要模型从聊天里提炼的印象，等这次的基础稳定后单独做（是否让私聊参与提炼，到时再定）。

### 4. 相同内容可以属于不同的人

`src/memory.js` 的去重键改为“规范化正文 + 涉及的人”（peers 去重、排序后连接）：

- 同一可见范围里，**同一个人**的相同内容只存一条；
- **不同的人**说了相同的话，各存各的。

迁移 `004` 按同样的规则重算了已有记录的去重键（排序用字节序，和 JS 一致；有测试核对）。

### 5. `self` 不再能看全部记录

| 请求者 | 能看到 |
| --- | --- |
| `self`（鱼自己） | 自我记忆（`self`）和公开记忆（`public`） |
| 会话 key | 这个会话的记忆（`conversation:`）、公开记忆 |
| 用户 key | 他的私事（`private:`）、对他的印象（`person:`）、他参与的群记录（`group:`）、公开记忆 |
| `OPERATOR`（运维） | 全部 |

聊天流程从此读不到任何不该读的内容，不再依赖事后过滤。CLI 的 `recall`、`export`、`forget`、`delete` 是运维操作，改用 `OPERATOR`。

### 6. 重启后仍认得出“引用奶蛙”

启动时从 Module 5 的消息记录（`inbound_messages`）取回最近 7 天奶蛙发出的消息（最多 2000 条）：重启后有人引用奶蛙以前的消息，仍算叫到它。

- `test/context.test.js`（PGlite 上，设置 `TEST_DATABASE_URL` 时也在真实 PostgreSQL 上）：代号按顺序分配、重启不变、并发分配不重号、租户独立；短期历史的顺序、24 小时时效、7 天清理；规则印象（群里只按群聊算、`person:` 备注出现、`private:` 私事绝不出现）；去重键带上“是谁”，并在只执行到 003 的库上跑迁移 004，核对重算结果与 JS 一致。
- `test/message.test.js`：重启后记得之前的对话；同一个人在群 A、群 B 代号一致、印象按所有群合计，群 A 的具体事不在群 B 召回；私聊内容在群里一点都不出现（含重启后），群里也看不出私聊过几次；两个人说同样的话各存一条；重启后引用奶蛙以前的消息仍算叫到它。

## 本模块没做的

- **模型提炼的印象**（兴趣、说话风格）：基础稳定后单独做，到时再定私聊是否参与。
- **具体事件跨会话**：按群单独开关，默认关闭，还没做。
- **好感度**：每条消息都加分，没有意义，留给 Module 8（人设与关系状态）。
- **用户要求删除自己的数据**：还没有。CLI 的 `forget` 只能按编号删一条记忆，`delete` 会清空整个租户的记忆；短期历史、关系、代号、事件都不受影响。属于“隐私合规”（商业客服待规划项）。

## 聊天原文存在哪里

| 位置 | 存什么 | 保留多久 |
| --- | --- | --- |
| `conversation_turns` | 最近几轮发给模型的消息（含原文） | 7 天，每天清理 |
| `memories` 的情节记忆 | 每次对话的前 60 个字 | 长期，这是“长期记忆”本身 |
| `events` 的检索事件 | Module 6 起只记查询的字数；**之前的记录里仍有查询原文** | 长期（事件表目前没有清理） |
| 录制文件（`ONEBOT_RECORD_FILE`） | 原始 OneBot 事件 | 只存本地 `data/`，手动管理 |
